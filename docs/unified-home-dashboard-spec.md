# 统一首页设计规格 — Admin & Operator

状态：v1 设计定稿
日期：2026-05-20
仓库：`aro-network/lumii-goldenyears-dashboard`
关联：`docs/quality-manager-page-spec.md`

## 1. 设计目标

将 Admin（集团管理 → 质量总览）和 Operator（站点管理 → 首页）两个首页统一为一致的视觉风格和信息架构。视觉一致，数据不同。

约束：
- 两个页面各自独立实现，不抽取共享组件
- 不改变页面与其他子页面的关系、路由结构、Shell 结构
- Admin 的 DashboardView 继续在 `QualityPage.tsx` 内
- Operator 的 HomeArea 继续在 `HomeArea.tsx` 内

## 2. 统一布局

两个角色看到相同的页面结构：

## 3. 角色差异对照

| 维度 | Admin（集团管理） | Operator（站点管理） |
|------|-------------------|---------------------|
| 文件 | `QualityPage.tsx` DashboardView | `HomeArea.tsx` |
| 标题 | 质量总览 | 首页 |
| 描述 | 监测各站点服务质量，发现站点差异 | 本站服务运营与质量概览 |
| 默认周期 | 月 | 周 |
| KPI 1 | 本期平均 S 分（副：满分 40） | 今日服务数（副：本站今日排期总量） |
| KPI 2 | 本期服务总次数（副：N 名员工） | 待排缺口（副：未分配服务数） |
| KPI 3 | 进步/退步人数（副：较上期变动） | 待复核（副：需确认的服务记录） |
| KPI 4 | 家属反馈率（副：B 分非默认值占比） | 本站 S 均分（副：满分 40） |
| 员工表数据范围 | 全部站点所有员工 | 仅本站员工 |
| 员工表"站点"列 | 显示 | 隐藏（本站员工无需显示） |
| 站点对比表 | 显示 | 不显示 |
| 周月切换 | 默认"月"，可切换到"周" | 默认"周"，可切换到"月" |

## 4. KPI 卡片设计

4 个卡片水平排列，等宽，响应式。每个卡片包含：
- 标签（12px，次要文字色）
- 主数值（22px，加粗）
- 副文字说明（11px，辅助灰色）

### Admin KPI（保持现有 DashboardView 不变）

| # | 标签 | 数值示例 | 副文字 |
|---|------|---------|--------|
| 1 | {周期}平均 S 分 | 32.8 | 满分 40 |
| 2 | {周期}服务总次数 | 168 | 10 名员工 |
| 3 | 进步 / 退步 | 6 / 2 | 较{上期}变动人数 |
| 4 | 家属反馈率 | 38% | B 分非默认值占比 |

### Operator KPI（新增）

| # | 标签 | 数值示例 | 副文字 | 数据来源 |
|---|------|---------|--------|---------|
| 1 | 今日服务 | 18 | 本站今日排期 | `summary.totalScheduledServices` |
| 2 | 待排缺口 | 3 | 未分配服务数 | `summary.unassignedServices` |
| 3 | 待复核 | 5 | 需确认记录 | `summary.recordsNeedReview` |
| 4 | 本站 S 均分 | 33.5 | 满分 40 | 新增：本站员工 S 分平均值 |

Operator KPI 中前 3 个使用现有 `HomeSummary` 数据源，第 4 个（本站 S 均分）需要从员工质量数据中计算。mock 阶段直接在前端硬编码。

## 5. 员工服务质量评分表

### 通用列定义

| 列 | 排序 | 说明 |
|----|------|------|
| 姓名 | 支持 | 可点击进入详情 Modal |
| 站点 | 支持 | 仅 Admin 显示 |
| 服务次数 | 支持 | 本期服务总次数 |
| S 均分 | 支持 | 总分（A+B+C+D），满分 40，语义色 |
| A 均分 | 支持 | 服务对象评价（0-10） |
| B 均分 | 支持 | 家属评价（0-10） |
| C 均分 | 支持 | SOP 符合度（0-10） |
| D 均分 | 支持 | 特殊识别（0-10） |
| 较上期 | 支持 | delta 值，带箭头+语义色 |

### 员工详情 Modal

点击姓名弹出详情 Modal，内容：
- 员工姓名 + 站点名
- ABCD 四维得分概览
- S 分趋势折线图（recharts，近 12 周/月）
- 关闭按钮

Admin 和 Operator 的 Modal 结构相同。

## 6. 周月切换

- 两个角色都有周/月切换按钮，位于标题栏右侧
- 切换按钮右侧显示日期标签：
  - 月：`2026年5月`
  - 周：`2026年 第21周（5/19 - 5/25）`
- 切换后 KPI 数值、员工表数据、趋势图均联动更新
- Admin 默认选中"月"，Operator 默认选中"周"

## 7. 对 HomeArea 的改动

### 移除内容
- AI 聊天界面（ChatStream + CommandInput）
- 右侧 sidebar 抽屉（KPI grid、重点关注、处理入口、最近动态）
- 面包屑按钮（home-breadcrumb）
- sidebar toggle 按钮
- 抽屉遮罩（home-drawer-scrim）

### 新增内容
- 标题区：标题 + 描述 + 周月切换 + 日期标签
- 4 个 KPI 卡片（今日服务、待排缺口、待复核、本站 S 均分）
- 员工质量评分表格（仅本站员工，无站点列）
- 员工详情 Modal（同 Admin）

### 不改动
- `SiteOperationsShell` 结构不变
- `SiteOperationsPage` 路由逻辑不变
- 其他 Area（SocialWorkersArea 等）不变
- Copilot 面板行为与其他子页面保持一致

### Copilot 行为

当前 Shell 在 `activeArea === "home"` 时隐藏 Copilot 按钮。改动后去掉此限制，使 home 与其他 area 行为一致。这是 Shell 中一行条件判断的修改。

## 8. 对 DashboardView 的改动

现有 DashboardView 已实现目标布局（4 KPI + 员工表 + 站点对比 + 周月切换），无需结构性修改。确认以下保持不变：
- 4 个 KPI 卡片内容和样式
- 员工表格（含站点列）
- 站点对比表
- 周月切换（默认月）
- 员工详情 Modal

## 9. CSS 策略

- Operator 首页样式写在 `siteOperations.css` 中，使用 `home-dashboard-*` 前缀
- 视觉规格对齐 `quality.css` 中的 `quality-kpi-card`、`qd-worker-table` 等样式
- 不共享 CSS 文件，各自独立
- 品牌色：Admin 使用 `#EB6420`（quality 暖橙），Operator 使用现有站点管理色系
