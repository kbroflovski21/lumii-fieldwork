# 0606 产品原型描述

> 基于 `0606-design-spec.md`，在现有 lumii-goldenyears-dashboard 代码基础上制作 UI-ready 前端原型。
> 纯前端展示，数据和交互全部 mock，不需要后端逻辑。

---

## 一、原型范围

### 1.2 原型要求

- **所有页面都要实现**：dashboard 三个角色（operator/admin/auditor）+ 护工 H5 + 家属 H5
- **登录流程保留**：所有页面使用用户名密码登录，保留登录 UI 和流程，但不做后台验证（前端 mock 验证）
- **所有数据和交互 mock**：不需要后台，数据内嵌前端

### 1.3 不在原型范围内

- AI 排班助手的实际 LLM 调用（用预设结果 mock）
- 实时 WebSocket 推送（用 setInterval + 静态数据模拟）
- 录音播放、语音通话
- 毫米波雷达的真实数据（热力图/动态回放用 Canvas 模拟占位）
- 声纹采集流程
- 后端数据持久化

## 二、实施策略

### 2.1 数据层

**复用 0604 已实现的 mock 数据**（mock/data.ts 和 mock/server.ts 已有大量新数据），在此基础上补充：

1. 排班相关数据：
   - `recurringScheduleRules` — 3-5 条周期性排班规则
   - 更新 `serviceSchedules` — 增加 matchStatus、plannedItems 等新字段
   - `policyConstraints` — 杭州地区的医保约束规则

2. 服务记录扩展：
   - 更新 `serviceSessions` — 增加 elderVerification、scheduleMatchStatus、plannedItems/confirmedItems
   - 热力图/动态回放占位数据

3. 机构数据（审计入口）：
   - `institutions` — 3-5 个机构/站点

### 2.2 UI 实施分 3 个并行工作流

**工作流 A：站点运营核心页面**（排班 + 进行中 + 已完成）
- 排班页面重大改造：日历视图 + 医保约束 + 额度面板
- 进行中服务页面（7 Tab 详情面板，实时ASR、飞检按钮等）
- 已完成服务页面（7 Tab 详情弹窗：服务总揽/六维核查/失能核查/录音与对话/服务质量/检查信息/反馈信息）

**工作流 B：护工 App 重构**
- 首页改为排班驱动
- 服务流程改造（结束时项目再确认 + 工时核对）

**工作流 C：医保局审计入口 + Admin 改造**
- 医保局 3 Tab（已有基础版，需增加机构管理 + 老人核查）
- Admin 新增服务目录管理 Tab
- Admin 运营总览改造

### 2.3 复用策略

| 现有资源 | 复用方式 |

| sw-* CSS 类 | 所有新页面统一使用 |
| SharedComponents（StatusBadge, FilterDropdown, ListToolbar, DetailPageShell 等） | 直接引用 |

### 3.2 已完成服务 — 7 Tab 详情弹窗

详情弹窗采用 7 Tab 结构：服务总揽 | 服务人员多维核查 | 长者失能程度核查 | 录音与对话 | 服务质量 | 检查信息 | 反馈信息

- **服务总揽**: 一览式摘要，含基本信息、六维核查N/6、失能核查状态、AI质量评分、排班匹配、风险识别、飞检有无、反馈计数
- **服务人员多维核查**: 六个维度各一张卡片（左边框颜色：绿=通过/红=异常/灰=缺失），含GPS定位距离、信标ID、声纹置信度、录音时长、雷达AI分析、照片上传时间
- **长者失能程度核查**: 登记等级 vs AI检测、热力图/回放占位、AI分析结论
- **录音与对话**: ASR日志 + 音频播放器占位
- **服务质量**: AI评分大字、总结、项目对比、违规、建议
- **检查信息**: 飞检详情或"未进行飞检"
- **反馈信息**: 回访 + 家属反馈列表

进行中服务详情面板采用相同 7 Tab 结构，但适配进行中状态（实时ASR、飞检按钮、"进行中"占位等）。
