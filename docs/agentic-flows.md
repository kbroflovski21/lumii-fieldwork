## 0. 参考源与产品边界

本文描述智能工牌驱动的最小业务闭环：工牌记录真实服务，后台自动规整服务事实，运营和管理通过聊天与结构化工作区查看、确认和追问；服务对象家属通过小程序或公众号订阅后，可以实时查询服务情况，并接收日报、周报和月报；运营可以按需导出服务日志，用于结算。

## 1. 产品主线

```text
运营激活智能工牌
  -> 可选分配服务人员
  -> 服务主管可选设置 SOP
  -> 运营可选排单
  -> 服务人员按键开始服务记录
  -> 工牌录音并上传
  -> 后台按需检查 SOP 和异常
  -> 服务人员按键结束服务记录
  -> 后台自动生成服务记录
  -> 后台更新服务对象档案
  -> 周期性生成洞察报告
  -> 家属通过小程序或公众号订阅、实时查询并接收日报/周报/月报
  -> 运营按需导出服务日志用于结算
  -> 运营、管理和服务主管通过聊天与工作区查看、确认、追问
```

核心原则：

- 工牌激活后即可使用。
- 运营可以指定服务人员，也可以让工牌动态混用。
- 服务主管可以设置 SOP；没有 SOP 时，工牌就是录音和服务记录设备。
- 运营可以排单；没有排单时，服务人员上门没有服务前提示，最终记录由录音推断生成。
- 录音事实是第一性数据。
- 结构化信息由后台自动推断，运营只处理例外。
- 家属端是订阅和查询入口，展示脱敏服务摘要、服务进展、状态变化和订阅报告。
- 服务日志导出是运营动作，用于结算、对账和留档；导出前需要筛选、确认和留痕。

## 2. Typical Use Cases and Flow

### F01 运营激活智能工牌

参与角色：站点运营

流程：

1. 站点运营扫描工牌设备码。
2. 手机号登录。
3. 创建或选择机构。
4. 工牌加入机构。
5. 可选指定服务人员，也可以保持动态混用。

结果：

- 工牌进入已激活状态。
- 工牌属于该机构。
- 后续服务记录归入该机构。

例外：

- 已绑定其他机构的工牌保持原机构归属。
- 原机构释放或客服验证后，工牌进入可重新绑定状态。

### F02 服务主管设置 SOP

参与角色：服务主管

流程：

1. 服务主管维护服务项目。
2. 服务主管设置 SOP 步骤、必问项、异常分支和完成标准。
3. SOP 生效后，后台可以在服务中检查规程执行情况。

结果：

- 有 SOP 时，后台可以检查漏项、异常和服务完整性。
- 没有 SOP 时，工牌仍可作为录音设备使用，服务结束后生成基础服务记录。

### F03 运营排单

参与角色：站点运营

流程：

1. 站点运营指定谁服务谁。
2. 输入方式可以是聊天、语音、表格、导入文件或结构化表单。
3. 系统把非结构化输入整理成任务，在结构化工作区中展示。

结果：

- 有排单时，服务人员上门前可以看到服务对象、地址、注意事项和服务项目。
- 没有排单时，服务人员仍可直接上门记录；后台根据录音内容推断服务对象和服务项目。

### F04 服务人员上门记录服务

参与角色：服务人员

流程：

1. 服务人员到达服务对象家中。
2. 按下工牌按钮开始记录。
3. 工牌录音并上传后台。
4. 服务结束后再次按按钮停止记录。

结果：

- 后台得到完整服务录音、开始时间、结束时间和设备身份。
- 后台根据语音内容识别服务人员、服务对象、服务项目和异常。

补充：

- 如果有 SOP，后台可以检查规程执行情况。
- 如果有输出通道，后台可以实时提示。
- 如果没有输出通道，则默认事后规整。

### F05 后台自动规整服务记录

参与角色：后台助手能力

流程：

1. 转写服务录音。
2. 判断服务对象、服务人员和服务项目。
3. 判断服务是否完整，例如语音是否中断、时长是否异常、关键环节是否缺失。
4. 如果存在 SOP，检查是否按规程执行。
5. 标出异常、风险、漏项和需要进入服务记录复核的事项。

结果：

- 生成服务人员服务记录档案。
- 更新服务对象档案。
- 形成服务记录中的复核、异常和缺失字段事项。

### F06 后台周期性生成洞察报告

参与角色：后台助手能力

流程：

1. 汇总服务记录、服务对象档案、异常、SOP 检查结果和服务趋势。
2. 周期性生成洞察报告。
3. 标出需要关注的服务对象、服务人员、站点和服务项目。
4. 按家属订阅关系生成面向家属的日报、周报和月报。

结果：

- 服务对象状态洞察。
- 服务人员规程执行洞察。
- 站点运营洞察。
- 异常趋势。
- 家属可接收的脱敏服务报告。

### F07 家属订阅、实时查询和接收报告

参与角色：服务对象家属

入口：

- 小程序。
- 公众号。

流程：

1. 家属通过小程序或公众号完成身份绑定和订阅。
2. 家属实时查询最近服务情况、服务对象状态变化和后续关注事项。
3. 系统按订阅频率推送日报、周报和月报。
4. 家属可以追问报告内容。

结果：

- 家属通过订阅和查询获得服务进展。
- 家属收到周期性报告，并可继续追问报告内容。

约束：

- 家属看到脱敏服务摘要、服务时间、服务内容、状态变化和风险提示。
- 原始音频、内部转写、审核备注、绩效信息、后台推断细节和机构内部处理记录属于内部运营资料。

### F08 运营导出服务日志用于结算

参与角色：站点运营

流程：

1. 站点运营按时间、站点、服务项目、服务对象、服务人员和状态筛选服务日志。
2. 系统展示服务记录、开始结束时间、服务时长、关联工牌、复核状态、异常标记和导出状态。
3. 站点运营确认导出范围和字段。
4. 系统生成可用于结算、对账和留档的服务日志文件。

结果：

- 运营获得结算所需的服务日志。
- 导出动作、筛选条件、操作者和导出时间被留痕。
- 存在需要复核的归属、未闭环异常或缺失字段时，系统提示运营确认或带标记导出。

### F09 运营和管理查看报告并主动查询

参与角色：集团管理、站点运营、服务主管

流程：

1. 用户进入聊天界面。
2. 用户直接提问，例如：
   - 最近哪些服务人员服务记录不完整？
   - 哪些服务对象最近状态变差？
   - 哪些服务没有按 SOP 做？
   - 本周异常最多的是哪个站点？
   - 本月哪些服务日志可以导出结算？
   - 哪些家属已经订阅报告？
3. 助手回答，并在工作区中展示结构化数据。
4. 用户确认、筛选、追问或导出。

结果：

- 用户通过聊天完成查询。
- 用户通过工作区查看结构化证据和明细。
- 运营处理服务记录复核、异常、整改、服务日志导出和结算留痕事项。

## 3. UI 框架

每一种角色进入系统后，都是：

```text
聊天主界面
  + 当前角色相关工作区
```

聊天负责：

- 提问
- 查询
- 总结
- 解释
- 生成建议
- 提醒异常

工作区负责：

- 展示结构化数据
- 展示服务记录复核事项
- 展示记录明细
- 展示报告和趋势
- 承载确认、修改、订阅、导出等动作

全局 UI 视觉和响应式规则见 [`global-ui-guidance.md`](global-ui-guidance.md)。本文只说明产品组织方式：

- 主界面是对话。
- 结构化内容放在规整工作区中。
- 结构化内容进入规整工作区。
- 用户从角色任务进入，由工作区承接对应结构化证据。

分角色工作区和动作边界见 [`role-ui-design.md`](role-ui-design.md)。

## 4. 自动行为

后台可以主动做这些事：

- 服务结束后自动生成服务记录。
- 服务结束后自动更新服务对象档案。
- 发现需要复核的服务记录归属时提醒站点运营确认。
- 发现服务中断、时长异常或 SOP 漏项时标记异常。
- 周期性生成运营报告、服务对象洞察和家属日报/周报/月报。
- 对需要整改、复查或结算导出确认的事项生成提醒。

自动行为不直接替人做高后果决定。涉及整改、结算导出、异常带标记导出和对外发送订阅范围之外的信息时，应由对应角色确认。
